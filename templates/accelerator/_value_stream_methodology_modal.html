Value Stream · Methodische Leitplanke

Methodik & Beispiel

Begriffe trennen: Capability = was das Unternehmen können muss; Value Stream = wie für einen Stakeholder Wert bzw. ein relevantes Ergebnis entsteht; Prozess = wie der konkrete Ablauf ausgeführt wird.

Value Stream sauber schneiden

Ein Value Stream beginnt mit einem klaren Auslöser (Trigger), beschreibt die fachliche Veränderung, durch die Wert entsteht, und endet mit einem relevanten Ergebnis (Outcome) für den Stakeholder.

  • Trigger und Empfänger/Stakeholder klar benennen.
  • Scope-In und Scope-Out ausdrücklich abgrenzen.
  • Vergleichbare Value Streams auf ähnlicher Flughöhe beschreiben (Granularität).

Phasen als Wertfortschritt

Eine Phase ist mehr als eine Tätigkeit: Was liegt vorher vor, was verändert sich fachlich und welcher relevante Zustand oder welches Ergebnis ist danach erreicht?

Ausgangszustand → fachliche Veränderung → Wertfortschritt → Ergebniszustand ist ein Denkmodell, keine Liste zusätzlicher Pflichtfelder.

Mehrere mögliche Value Streams

Als pragmatische Auswahlhilfe kann Geschäftliche Bedeutung × Veränderungsbedarf (Business Importance × Transformation Need) verwendet werden. Berücksichtigen Sie z. B. strategische bzw. wirtschaftliche Relevanz und Stakeholder-Wert sowie Engpässe, manuelle Aufwände, Qualitätsprobleme oder Änderungsdruck. Daraus entsteht kein neues Pflicht-Scoring.

Kurzes Beispiel

Value Stream
Beschaffungsbedarf bis Bestellung
Trigger
Bestätigter Beschaffungsbedarf liegt vor.
Stakeholder
Bedarfsträger und Einkauf.
Outcome
Fachlich und kaufmännisch freigegebene Bestellung wurde ausgelöst.
Scope-In
Bedarf konkretisieren, Anbieter/Angebote prüfen, Entscheidung und Bestellung.
Scope-Out
Wareneingang, Rechnungsprüfung und Zahlung.
Beispielphase
„Angebote vergleichbar machen“: Aus unterschiedlich strukturierten Angeboten entsteht eine fachlich vergleichbare Entscheidungsgrundlage.
Nach der Fokusphase folgt die Prozessanalyse und anschließend der Lösungsraum. KI ist dabei eine mögliche Option neben organisatorischen, regelbasierten und klassischen technischen Lösungen.
